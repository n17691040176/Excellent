# 城市合伙人订单退款约束（2026-09-11）

## 已确定规则

- 城市合伙人席位订单（`CITY_PARTNER_ORDER`）不支持用户端或后台主动退款。已取得席位、付款后未取得席位、结算异常、缺失席位购买记录，均返回 HTTP 409 和“城市合伙人订单不支持退款”。
- 规则依据订单类型判断，切换原/新分润模式不会解除限制。采用新分润模式的普通商品订单继续使用已有售后规则；历史商品类型席位轮换订单的成功轮换退款限制保留。
- 未付款仍可取消；退款禁令不涉及接替成功后给上任合伙人的本金返还。
- 保留取消后支付晚到、重复扣款的原路退回，避免多收款。已持有席位和其分润不因重复扣款退回而撤销。
- 政策调整前已受理退款的回调、同步和在途重试继续对账；不允许利用已失败/已关闭/异常退款记录新发起席位退款。

## 实现

订单服务统一拦截退款发起和内部直接退款路径；微信退款服务在持有交易和订单锁后再次校验，不能绕过订单接口新建席位退款。已受理退款的完成路径保留原有账务校验和幂等逻辑。

移动端、后台列表和详情返回 `can_refund=false`；两端隐藏席位退款操作，购买确认及详情明确“不支持退款”。席位失败提示改为联系平台处理，已完成的历史退款不会继续显示席位待处理提示。

付款后未取得席位的订单将保持待平台处理状态，不自动变为成功、不开放主动退款；本次未新增异常席位人工履约工具。

## 验证

- 新增 13 项专项测试：两种模式 × 四种订单状态的用户及后台接口，微信直接退款防绕过，未付款取消，历史在途退款完成和重放，晚到/重复扣款退回。
- 完整后端及文档/业务边界回归：411 passed，2 subtests passed，无失败、无跳过；包含实际本地 MySQL 测试。1 条既有测试依赖弃用警告。
- 后端全量 Ruff 和改动前端文件 ESLint 均通过。
- 后端、后台及移动端 Docker 镜像构建成功。本次只更新本地测试环境，不部署生产。
- 更新后的本地容器 5 个服务全部健康，三个健康接口均 HTTP 200；实时抽查 60 个席位订单均不可退款，已完成/付款未取得席位订单的后台退款请求均返回 HTTP 409。
