# 功能缺口清单（2026-04-02）

- 文档日期：2026-04-02
- 目标：对照 `docs/开发文档-校对版.md`、`docs/接口设计-校对版.md`、`docs/数据库设计-校对版.md`，梳理当前仓库仍未完全闭环的能力项
- 审查范围：`server/`、`admin-web/`、`mobile-h5/`
- 说明：本清单只记录“当前仍未完整落地”或“仅完成轻量实现”的部分；已完成的能力不再重复列为缺口

---

## 1. 总体判断

- 当前仓库已经具备 APP 一体化商城的主链路：认证、团队、邀请返现、套餐、四大专区、资产体系、本地生活、后台管理、移动端 H5。
- 当前最主要的缺口，已经从“有没有页面/接口”转向“运营深度、配置深度、正式商用能力、工程化治理”。
- 后台商品专区规则配置已落地，当前可直接维护复购区、自营商城、爆款区、本地生活的商品级配置；该项不再列为缺口。
- 若目标是继续内部联调和业务审查，当前代码已可持续推进；若目标是正式商用测试，仍建议优先补齐 P0 / P1 项。

---

## 2. P0 缺口：进入正式业务测试前建议优先补齐

### 2.1 后台运营 CRUD 仍不完整

当前状态：
- 后台已具备用户、供应商、资格审核、提现审核、本地生活核销、专区规则配置等能力。
- 后台已补齐专区商品的新增、编辑、提审、审核、上下架、删除能力。
- 后台已补齐套餐的新增、编辑、上下架、删除能力。
- 后台已补齐本地生活商家、门店、服务、分佣规则的基础 CRUD。
- 但大量模块仍偏“查看型后台”，不是“完整运营型后台”。

主要缺口：
- 套餐管理已补齐基础 CRUD 和状态流转，但套餐权益明细、权益模板化和 benefit 配置仍未形成独立运营界面。
- 本地生活已补齐基础 CRUD，但商家审核流、复杂分账、设备收益规则联动和清结算后台仍待增强。
- 团队管理页面目前更偏当前团队查看，仍不是全量团队运营管理台。

影响：
- 当前后台更适合单人开发阶段的联调与轻量运营，不适合高频日常运营。

### 2.2 四大专区定价与活动规则仍未完全产品化

当前状态：
- 下单校验已按专区收口：禁止跨专区混单、复购区校验套餐资格、自营商城校验兑换券和 AI 券比例、爆款区限制资产类型与限购、本地生活校验基础抵扣与上架状态。
- 后台也已支持商品级专区规则配置。

主要缺口：
- 复购区“4-6 折复购”仍未沉淀为独立价格引擎，仅有规则字段和基础校验。
- 自营商城“兑换券 5-7 折当现金使用”的规则已做比例校验，但还未扩展成更细粒度商品级营销策略。
- 爆款区缺少活动批次、时间窗、抢购场次、库存锁定等完整活动模型。
- 本地生活分佣和设备收益已有规则字段与管理侧查询，但支付前强约束、分账明细和运营配置深度仍待增强。

影响：
- 当前已经不是“无专区规则”的状态，但距离完整商业化活动引擎还有距离。

### 2.3 招商审核链路仍待深化

当前状态：
- 供应商申请、我的供应商、协议上传、上架资格申请、后台资格审核已落地。
- 入场费资格、5500 套餐额度、区县/市代理额度、一件代发、市场价 2 折红线、重复占用校验，已接入商品上架资格申请与审核链路。
- 代理资格审核通过后，已自动回写 `used_quota` 并同步升级用户业务身份。

主要缺口：
- “一手资源证明、协议附件、售后/质量承诺”目前仍主要以 URL 和说明字段承载，尚未形成结构化材料清单与强审计留痕。
- 商品上架资格审核结果已联动到供应商商品提审、审核通过、上架环节，也已支持自动绑定供应商商品归属；资格占用台账视图已补齐，但仍未做到自动上架或更细粒度的归属回滚策略。
- 招商后台已补齐资格来源、剩余额度、协议状态、商品合规快照、资格占用/释放台账，但仍缺协议到期预警、材料完整度评分、额度消耗趋势图等更深入运营视图。

影响：
- 当前招商流程已具备核心自动化治理能力，可支撑联调和规则审查；若进入更正式的运营阶段，仍需继续补强材料治理与运营视图。

### 2.4 支付仍是演示链路

当前状态：
- 普通商品订单、本地生活订单、套餐订单都已支持演示支付流。

主要缺口：
- 尚未接入正式第三方支付渠道。
- 缺少支付回调、幂等签名校验、退款回调等正式支付治理能力。

影响：
- 适合当前业务演示和前后端联调，不适合直接上线商用收款。

## 3. P1 缺口：进入小范围运营前建议补齐

### 3.1 首页运营位仍偏轻量

当前状态：
- APP/H5 首页已具备四大专区入口。
- `GET /api/v1/app/home` 已返回专区入口、空 banners、空 notices。

主要缺口：
- 轮播图、公告、推荐位、专题位尚未后台化。
- 各专区首页推荐策略、爆款位、本地生活精选位未形成统一配置中心。

### 3.2 后台账号与角色管理仍偏展示型

当前状态：
- 后台已具备角色口径菜单、路由拦截、部分按钮级权限控制。
- 超级管理员与团队管理员的数据范围控制已覆盖核心链路。

主要缺口：
- 仍未形成独立后台管理员账户 CRUD。
- 角色管理页面主要是静态展示，尚未形成完整角色配置后台。
- 更细粒度的按钮权限、资源权限、数据权限矩阵仍待下沉。

### 3.3 列表接口仍未统一服务端分页化

当前状态：
- 当前大部分列表接口直接返回数组。
- 前端的搜索和筛选，很多仍在本地计算。

主要缺口：
- 缺少统一 `page / page_size / total` 返回结构。
- 缺少统一的服务端关键字、状态、时间范围筛选参数。

影响：
- 在 1 万用户量级下短期仍可使用，但后续数据量增长后，后台体验和接口稳定性会先遇到瓶颈。

### 3.4 成功响应体仍未统一返回 `request_id`

当前状态：
- 中间件已生成 `X-Request-Id` 响应头。
- 错误响应也已具备错误上下文。

主要缺口：
- 成功响应体尚未统一显式透出 `request_id` 字段，不利于线上排查联调问题。

### 3.5 Celery 已配置但尚未正式挂入主链路

当前状态：
- Celery 配置和任务文件已存在。

主要缺口：
- 结算、通知、收益处理仍以同步业务流为主。
- 当前未见核心业务节点 `delay()` / `apply_async()` 的稳定落地。

影响：
- 异步能力目前更像预留基础设施，而不是已经在线上运行的主流程能力。

## 4. P1 缺口：数据库与工程治理

### 4.1 规划中的治理增强表仍未全部落地

当前仍缺的重点表：
- `admin_accounts`
- `audit_logs`
- `supplier_products`
- `asset_transfer_records`

参考：
- `docs/当前数据库实现对齐说明-2026-04-02.md`

### 4.2 当前仍未接入迁移体系

当前状态：
- 数据库初始化仍依赖 `Base.metadata.create_all()`。

主要缺口：
- 缺少 Alembic 等迁移体系，不利于后续字段变更、索引演进和版本发布。

### 4.3 `schema.sql` 仍偏轻量初始化脚本

当前状态：
- ORM 层已有大量外键关系。

主要缺口：
- `server/sql/schema.sql` 尚未完整下沉为强约束 DDL，物理外键与数据库治理仍偏轻量。

---

## 5. P2 缺口：体验与平台化增强

### 5.1 移动端分享仍以复制为主

当前状态：
- 邀请码和邀请链接当前以复制为主要交互方式。

主要缺口：
- 尚未接入更完整的分享面板、原生 App 分享桥或微信生态分享能力。

### 5.2 后台配置中心体验仍待继续增强

当前状态：
- 招商中心已补齐专区商品规则配置抽屉。

主要缺口：
- 套餐、资产、本地生活规则等仍缺少更完整的配置化表单、审批弹窗和批量操作体验。

### 5.3 首页视觉内容仍偏静态

当前状态：
- 移动端首页已具备专区框架。

主要缺口：
- 仍缺少轮播、专题、精选、活动氛围等更强运营视觉内容。

---

## 6. 建议的下一阶段开发顺序

### 第一批：优先补“业务可运营”
1. 套餐权益模板化与 benefit 配置
2. 招商代理额度规则与协议校验自动化
3. 团队全量管理台与更细粒度运营动作
4. 本地生活商家审核流与清结算增强

### 第二批：补“正式业务能力”
1. 正式支付渠道与支付回调
2. 退款 / 售后链路
3. 爆款区活动批次与库存锁定
4. 自营商城更细粒度营销策略

### 第三批：补“工程治理与平台化”
1. 服务端分页与统一筛选协议
2. Alembic 迁移体系
3. 审计日志与后台管理员账户体系
4. Celery 正式接入结算 / 通知 / 收益任务
5. 首页运营位配置中心

---

## 7. 当前审查建议

- 若你现在重点审查“业务规则有没有跑偏”，优先看四大专区规则、招商资格审核、资产抵扣链路。
- 若你现在重点审查“权限有没有漏洞”，优先看团队管理员数据隔离与后台范围控制。
- 若你现在重点审查“后台能不能支撑运营”，优先看套餐、商品、本地生活的 CRUD 深度。
- 若你现在重点审查“什么时候能上正式商用测试”，优先看支付、分页、迁移体系、异步任务接入。
