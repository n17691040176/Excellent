## 1. 接口设计目标

本接口文档面向以下客户端：
- APP 用户端
- 管理后台 Admin Web
- 后续可扩展商家端 / 代理端

设计目标：
- 统一 RESTful 风格
- 统一响应结构
- 明确角色权限边界
- 覆盖四大专区、招商、套餐、资产、本地生活核心流程
- 便于直接映射 FastAPI 路由与 Swagger 文档

## 2. 基础规范

### 2.1 基础前缀
- 统一前缀：`/api/v1`
- 用户端：`/api/v1/app/*`
- 后台端：`/api/v1/admin/*`
- 公共认证：`/api/v1/auth/*`

### 2.2 请求头
- `Authorization: Bearer <token>`
- `Content-Type: application/json`
- `X-Request-Id: <uuid>`（可选）

### 2.3 统一响应结构
```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "request_id": "uuid"
}
```

### 2.4 分页结构
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "page": 1,
    "page_size": 20,
    "total": 100
  },
  "request_id": "uuid"
}
```

### 2.5 错误码
- `0` 成功
- `40001` 参数错误
- `40101` 未登录
- `40102` token 无效
- `40103` token 已过期
- `40301` 权限不足
- `40401` 资源不存在
- `40901` 业务冲突
- `50001` 系统异常

## 3. 鉴权与权限规则

### 3.1 登录态
- APP 用户登录后持有 JWT
- 管理后台管理员登录后持有 JWT
- token 统一由后端解析并校验

### 3.2 角色访问边界
- `SUPER_ADMIN`：全部后台接口
- `TEAM_ADMIN`：团队范围内后台接口
- `USER`：APP 接口，不允许后台登录

### 3.3 数据隔离原则
- 用户只能看自己的订单、地址、资产、提现
- 团队管理员仅能看本团队用户与数据
- 本地生活商家数据需按商家归属或平台角色限制

## 26. 关键接口业务校验清单

### 26.1 套餐下单
- AI 券抵扣不超过套餐上限
- 套餐支付成功后自动赠送兑换券
- 若配置积分补贴，则生成积分发放记录

### 26.2 复购区下单
- 用户必须有有效套餐资格
- 商品必须属于复购区
- 复购折扣价格必须命中专区配置

### 26.3 自营商城下单
- 兑换券抵扣不得超过商品或专区设置上限
- 支付成功后自动赠送 20% AI 券

### 26.4 爆款区下单
- 校验活动时间
- 校验限购次数
- 校验库存
- 仅允许积分/余额/混合支付规则内的方式

### 26.5 供应商入驻
- 自动计算入场费金额
- 推荐会员奖励按 15% 预计算或支付后生成

### 26.6 商品上架资格审核
- 校验是否已缴纳入场费
- 校验是否具备代理资格
- 校验是否有套餐给予的上架资格
- 校验未超过可上架数量上限
