## 5. 当前已打通的关键业务流

### 5.1 邀请返现流
1. 用户注册绑定邀请码
2. 形成一级 / 二级邀请关系
3. 下级完成支付后，上级佣金冻结
4. 订单确认或本地生活核销后，冻结佣金转可提现
5. 用户发起提现申请，后台审核

### 5.2 套餐资产联动流
1. 用户下单套餐
2. 可使用 AI 券按比例抵扣
3. 支付后发放兑换券
4. 同时发放积分补贴
5. 若存在上级，发放推荐赠券
6. 形成套餐资格与上架额度

### 5.3 本地生活履约流
1. 浏览服务列表
2. 创建服务订单
3. 支持积分 / 余额抵扣
4. 订单支付后进入待核销状态
5. 核销成功后订单确认完成
6. 结算返现和联盟收益逻辑

### 5.4 资产流转流
- 余额：设备收益 / 广告收益 / 爆款消费 / 本地生活消费
- 积分：套餐补贴 / 转赠 / 抵扣消费 / 提现
- 兑换券：套餐赠送 / 签到赠送 / 自营商城抵扣
- AI 券：自营商城返券 / 套餐抵扣

## 6. 当前与规划文档相比的已落地差异

### 6.1 已超出原始最低需求的部分
当前代码已经超出最早“轻量电商后端 + 管理后台 + H5”的最低版，实际已提前落地以下扩展：
- 套餐体系
- 四大专区商品口径
- 四类资产体系
- 本地生活商家、服务、订单、核销
- 供应商/代理相关模型
- 用户侧演示支付链路
- 本地生活订单专属页

### 6.2 规划中提出但当前仍偏轻量实现的部分
以下能力当前是“轻量版落地”，后续如需商用深化还应补强：
- 正式支付渠道接入，目前仍为演示支付
- 图片上传 / 协议文件真实存储，目前以 URL 字段承载
- 后台商品、套餐、商家的完整 CRUD，目前以列表/查看为主，少量操作为辅
- 订单售后 / 退款 / 风控规则仍未深化
- 爆款区限时场次、限购、库存锁定仍未做完整活动引擎
- 自营商城兑换券兑换期权、股权逻辑尚未单独实现为独立业务流程
- 本地生活联盟分佣比例当前以规则数据模型 + 管理端查询为主，未扩展出复杂清结算后台
