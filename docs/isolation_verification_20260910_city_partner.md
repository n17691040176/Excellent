## 1. 本次采用的业务口径

商品售价、成本在后台商品编辑中手填；城市合伙人奖和直推奖在商品规则中手填，金额精确到分。城市合伙人商品规则启用后，成本必填，所有理论奖励合计不得超过售价减成本。

“再往上 7 级”按以下关系实现：买家的直接推荐人只拿直推奖；从直接推荐人的上级开始，再向上分七层。因此，完整发放需要买家有八位祖先。此关系是对用户原话的实施解释，未收到对补充澄清问题的单独答复；此前“直接推荐人同时拿直推和第 1 层奖”的行为已停止用于新付款。

第 n 层每件奖励 = 直推金额 ÷ 2ⁿ，n 为 1～7。每层独立按理论值向下取到分，再乘购买件数；不能用上一层已经舍入的金额继续计算。后台显示七层预览；接口拒绝手工提交首层金额、层数、递减比例。这些旧数据库字段仍兼容保留，但不能覆盖新算法。

例：售价 1600、成本 700、城市奖 100、直推奖 400，购买一件且城市及上级完整：

| 受益对象 | 元 |
|---|---:|
| 收货城市的当前合伙人 | 100.00 |
| 买家的直接推荐人 | 400.00 |
| 推荐人的上级，向上第 1 层 | 200.00 |
| 向上第 2～7 层 | 100.00、50.00、25.00、12.50、6.25、3.12 |
| 公司剩余金额 | 3.13 |
| 合计 | 900.00 |

缺失城市持有人或对应上级的份额归公司，不向其他人补位。城市持有人恰好也是推荐人时，可以按不同角色分别获奖，账户累计必须等于其全部流水。

城市席位按标准省、市组合唯一；允许空缺，但最多一名当前持有人。数据库唯一约束保护并发创建，冲突返回 409。持有人不能为自己当前持有的席位创建接替订单，付款履约时也再次检查。已成功购买的重复支付回调仍按幂等处理；历史未付自购订单付款后保留付款事实，拒绝履约并允许按未履约路径退款。

## 2. 两套模式如何隔离

- 全局模式控制商品分润。商品在支付成功处理时读取并锁定模式，保存模式与规则快照；不是按下单时间选模式。
- 已生成的分润流水释放、撤销使用原金额，不随以后切换模式、改商品规则或换城市持有人重算。新模式在付款时保存规则快照；原模式区域代理奖仍在完成时首次读取配置计算，不能概括为原体系所有奖励均已在付款时冻结。原模式仍使用原专属固定金额/比例、普通分销、复购和区域代理规则。
- 新模式商品不进入原分销和区域代理路径。商品未开启新规则时，不产生新奖励，也不会回退原模式。
- 更新商品规则仅合并实际提交字段，避免请求默认值把另一套规则清零。模式切换本身不修改商品规则；快速切换的审计版本使用独立唯一值。
- 支付模式及区域分红读取刷新已锁定记录，避免同一会话缓存旧状态。新旧流水若已混入同一订单，后续冻结、结算和退款会阻止继续动账并要求对账，不静默重算历史数据。
- 两套商品流水分表记录，但用户佣金汇总余额共用；共用余额是既有设计。锁定后刷新并逐笔写入，防止并发或同一用户连续获奖时覆盖余额。

原体系还存在一个可复现的历史累计错误：数量 2、利润池 1800 时，同一上级获直推 180 和团队奖 54，原累计可能只剩 54，释放后冻结余额可能为 -180。本次补齐事务内写入，累计改为 234；发奖对象和金额规则保持一致。没有批量重写既有历史账务。

## 4. 仍然有效的范围和政策限制

- 全局切到 ORIGINAL 不会关闭城市席位交易；席位购买是独立业务，不属于普通商品分润切换。
- 配送订单确认完成立即释放佣金，尚无额外售后冻结期；完成后的普通退款受现有订单政策限制。已成功取得城市席位不支持普通退款，特殊全量冲正未实现。
- 已释放佣金如果被使用或提现，余额不足可以阻止退款收回；本次不新增负余额追偿政策。
- 商品订单明细售价在下单时保存，成本在付款时取值；积分/余额抵扣不缩小该商品分润池。成本变化致超池时保留付款、暂停履约并提供退款处理，不减少奖励强行结算。
- 真实微信、支付宝收退款、提现到账和生产全量历史账务不在本轮验证范围。设计文档的其他待定条款仍待确定。
