# 城市合伙人商品分润模式开发文档

**状态：待审查**  
**版本：v1.1-draft（2026-09-10 规则修订）**
**日期：2026-09-10**

本次明确：售价、成本、城市合伙人奖、直推奖手动填写；七层奖励可选择按直推奖 50% 自动递减或逐级手动填写；每市仅一名当前合伙人，禁止自己接替自己。层级关系按“直推上级领取直推奖，再从他的上级开始向上七层”实现，不重复给直推上级第 1 层奖。其余待定项继续保留，不将本次修订视为整份文档已最终定稿。

## 1. 目标

新增“城市合伙人商品分润模式”，同时严格保留当前“原商品分润模式”。两套模式全局互斥，同一笔订单只能按其中一种模式计算分润。

原版已留存：

```text
Git tag: original-commission-20260909
Commit: 79c012b
```

## 2. 模式定义

### 2.1 原模式 `ORIGINAL`

原有商品分润体系，继续保留：

- 原商品分润规则；
- 原一级、二级或现有上级分润；
- 市级代理；
- 区域代理；
- 原市级代理及区域代理收益；
- 原有冻结、释放、结算、退款收回逻辑。

原模式不得被新模式覆盖或重算。

### 2.2 城市合伙人模式 `CITY_PARTNER`

新模式包括：

- 城市合伙人席位；
- 城市合伙人席位购买及轮换；
- 城市合伙人商品分润；
- 直推奖；
- 向上最多 7 层分润；
- 公司账户；
- 运维部账户。

**新模式不存在市级代理，也不产生市级代理分润。**

新模式只沿用原系统的省、市数据标准识别订单城市，不沿用市级代理角色。

## 3. 两套模式边界

| 项目 | 原模式 | 新模式 |
|---|---|---|
| 模式编码 | `ORIGINAL` | `CITY_PARTNER` |
| 市级代理 | 有 | 无 |
| 区域代理 | 有 | 不参与 |
| 城市合伙人 | 不参与 | 有 |
| 原商品分润 | 有 | 不使用 |
| 原市级代理收益 | 有 | 无 |
| 直推奖 | 不使用新规则 | 有 |
| 上级分润 | 原规则 | 最多 7 层 |
| 城市识别 | 原区域数据 | 原省、市数据标准 |
| 订单退款 | 原模式逻辑 | 新模式逻辑 |

## 4. 后台模式开关

### 4.1 全局互斥

第一版采用全平台统一模式，不能按商品、分类或城市分别切换。任意时刻只有一个模式生效：

```text
原商品分润模式
城市合伙人商品分润模式
```

### 4.2 订单模式快照

每笔订单在支付成功时锁定模式，至少记录：

```text
commission_mode
commission_rule_version
mode_locked_at
```

新模式商品订单还记录：

```text
province
city
city_partner_user_id
city_partner_rule_snapshot
sale_price_snapshot
cost_price_snapshot
profit_pool_snapshot
```

规则：

- 切换前支付成功的订单按原模式；
- 切换后支付成功的订单按新模式；
- 历史订单结算不读取当前后台模式；
- 历史订单退款不读取当前后台模式；
- 已冻结分润继续按订单原模式释放或收回；
- 一笔订单不得同时生成两套模式的分润。

2026-09-11 补充：切回 `ORIGINAL` 后，移动端隐藏城市合伙人入口，不展示席位列表、持有城市、报价及购买规则，直接访问席位页面显示“暂未开放”；禁止新建席位订单和重新发起未付款席位订单的支付。切回 `CITY_PARTNER` 后恢复入口及可购买席位。页面每次进入和前台停留期间定期读取当前模式，购买请求由服务端按当前模式校验。

历史席位订单和已产生的佣金记录继续可查，后台管理和对账保留；城市合伙人席位订单不开放用户端或后台主动退款。切换前已发起的第三方支付可能延迟回调，收到真实付款后仍按既有订单处理履约与异常退款，不因入口关闭丢弃付款事实。

### 4.3 后台审计

每次切换记录：

```text
原模式、新模式、切换时间、操作管理员、切换原因
切换前未完成订单数量、冻结分润金额
```

切换到新模式前应校验：公司账户、运维部账户、新商品规则、城市配置、成本售价、退款规则均已配置。

## 5. 城市合伙人席位轮换

### 5.1 席位

每个省、市组合最多一个当前有效城市合伙人。城市合伙人与市级代理完全不同；新模式不读取原市级代理身份。

当前持有人不可再次购买自己的同城席位。创建购买订单和支付履约时都必须检查；同一已成功订单的支付回调重试属于幂等确认，不属于再次接替。

### 5.2 首次购买

设首次价格为 `P`：

```text
购买者上级：P × 10%
公司账户：P × 90%
```

无上级时，原本给上级的 10%进入公司账户。购买成功后购买者成为当前城市合伙人。

### 5.3 后续接替

设：

```text
P_old = 上一任购买价格
P_new = 新一任购买价格
A = P_new - P_old
```

资金分配：

```text
上一任本金返还：P_old
上一任增值奖励：A × 40%
公司账户：A × 30%
新购买者一级上级：A × 10%
运维部账户：A × 20%
```

分配合计为 `P_new`。新购买成功并完成平台确认后：

- 新购买者成为当前城市合伙人；
- 上一任立即失去资格；
- 上一任获得本金返还及增值奖励；
- 当前价格更新；
- 历史轮换记录保留。

### 5.4 价格

```text
下一次价格 = 当前成交价格 ×（1 + 后台增长比例）
```

后台可设置价格上限：

```text
已设置上限：下一次价格 = min(计算价格, 上限)
未设置上限：不限制
```

达到上限后，增值金额按实际成交价减上一任购买价计算。比例调整只影响未来轮换，不修改历史价格。

### 5.5 并发

同一城市同一时间只能有一个成功接替者。购买流程需要锁定城市席位和当前价格，支付成功后校验价格版本，生成结算，再切换合伙人。

## 6. 新模式商品分润

### 6.1 分润池

```text
商品分润总额 = 实际卖价 - 商品成本
```

商品售价和成本价由后台手动填写；城市合伙人金额及直推奖金额也手动填写。向上七层支持两种方式：AUTO 根据直推奖逐级减半；MANUAL 分别填写七级金额（每级可为 0，最多两位小数）。层数固定七级，自动模式的递减比例固定 50%。两种方式均校验整个分润池。

双头灶示例：

```text
卖价：1,600 元
成本：700 元
分润总额：900 元
```

### 6.2 分润对象

新模式仅包括：

- 当前城市合伙人；
- 购买者一级直推上级；
- 向上第 1 至第 7 层上级；
- 公司尾差账户。

新模式不包括：

- 市级代理；
- 区域代理；
- 原一级、二级分润；
- 原商品专属分润。

### 6.3 金额规则

双头灶 900 元分润池：

| 对象 | 金额 |
|---|---:|
| 城市合伙人 | 100.00 |
| 直推奖 | 400.00 |
| 上级第 1 层 | 200.00 |
| 上级第 2 层 | 100.00 |
| 上级第 3 层 | 50.00 |
| 上级第 4 层 | 25.00 |
| 上级第 5 层 | 12.50 |
| 上级第 6 层 | 6.25 |
| 上级第 7 层 | 3.12 |
| 公司尾差 | 3.13 |
| **合计** | **900.00** |

直推奖 400 元不参与 50%递减。向上分润从第 1 层 200 元开始：

```text
上级第 n 层理论金额 = 直推奖 × 50%^n，n = 1...7
```

直推奖给购买者的直接上级；上述第 1 层给直推上级的上级（购买者关系链的第 2 位祖先），第 7 层给购买者关系链的第 8 位祖先。直接上级在本例只领取 400 元，不同时领取 200 元。计算保留理论精度，每层实际金额按件向下取整到分。

金额处理：保留小数点后两位，第三位及以后直接向下取整。

手动设置示例：七级各填 0.20 元，则每件七级合计 1.40 元；直推奖、城市合伙人奖另外按手动配置发放。该设置适用于任意商品，不根据商品名称或类别自动识别燃料。金额按件乘以购买数量，与直推奖是否为 0 无关。未启用新模式商品分润时不发放。

两种方式互切时保留已填写的手动金额，自动模式忽略该数组。每笔付款快照保存所选方式、七级金额和计算策略；已付款订单后续结算及退款使用原流水，商品配置变更不重算历史。

### 6.4 尾差

逐层向下取整产生的尾差进入公司账户。若上级不足 7 层，未发放层级金额也进入公司账户；不得虚构用户或改发给其他层级。

如果没有城市合伙人，城市合伙人应得金额进入公司账户；新模式下不得转给市级代理。

如果没有上级，直推奖及对应上级层级金额进入公司账户，最终是否拆分展示由产品确认，本文默认均进入公司尾差账户。

### 6.5 分润池硬约束

```text
实际发放分润总额 ≤ 商品卖价 - 商品成本
```

后台保存商品新模式规则时必须校验，禁止配置导致超发。商品成本或售价发生变化时，应按订单成本、售价快照结算。

### 6.6 计算单位

本文默认按商品件数计算。购买 2 件时，各项固定金额均乘以 2。若业务要求按订单只发一次，需要在开发前改为订单级规则。

## 7. 城市和订单归属

本文默认使用订单收货地址的省、市匹配城市合伙人：

```text
陕西省 / 西安市 → 西安市城市合伙人
```

商品分润冻结时锁定：

```text
订单省、市
当时有效的城市合伙人用户
商品售价和成本
```

后续城市合伙人轮换不改变已经锁定的订单归属。

## 8. 订单结算和退款

### 8.1 结算入口

```text
ORIGINAL → 原商品分润结算器
CITY_PARTNER → 城市合伙人商品分润结算器
```

禁止同一订单先调用原结算器、再调用新结算器。

### 8.2 冻结和释放

建议新模式继续采用现有“先冻结、后释放”的生命周期，但新模式使用独立规则快照和流水：

```text
支付成功
→ 锁定模式和规则
→ 订单完成或达到结算条件
→ 生成新模式冻结分润
→ 售后期结束后释放
→ 退款时按原流水冲正
```

### 8.3 退款

退款按照订单原始模式处理：

```text
原模式订单 → 原模式分润收回
新模式订单 → 新模式分润收回
```

新模式退款需要冲正城市合伙人、直推奖、各层上级、公司账户、运维部账户和尾差账户的对应流水。不能因后台当前模式已经改变而改变历史退款逻辑。

## 9. 数据和账户

### 9.1 席位轮换流水

至少记录：

```text
城市、上一任用户、新一任用户
上一任购买价格、新一任购买价格、增值金额
本金返还、增值奖励、公司分配、上级奖励、运维部收入
结算状态、支付订单、时间、规则版本
```

### 9.2 商品分润流水

至少记录：

```text
订单、商品、模式、规则版本
售价、成本、分润池
受益用户、分润角色、层级
原始计算金额、取整后金额、尾差金额
冻结、结算、取消状态
```

建议区分：

```text
公司账户
运维部账户
城市合伙人席位结算账户
商品分润账户
公司尾差账户
```

城市合伙人席位轮换资金和商品订单分润不得混为无法区分的一类流水。

## 10. 后台功能

### 10.1 模式管理

显示当前模式、生效时间、最近切换人和原因，并支持切换。切换前展示待结算订单、冻结金额和配置校验结果。

### 10.2 城市合伙人管理

查看和配置：

- 城市；
- 当前合伙人；
- 初始价格；
- 当前价格；
- 增长比例；
- 价格上限；
- 轮换次数；
- 任期时间；
- 购买订单；
- 历史轮换结算。

### 10.3 商品新模式规则

建议配置：

```text
是否参与新模式
城市合伙人金额
直推奖金额
七级分润方式（按50%递减 / 手动设置）
手动模式：第1至第7级金额，单位元/件
自动模式：上级起始金额（只读，由直推奖×50%计算）
上级层数（固定7，不可编辑）
层级递减比例（固定50%，不可编辑）
尾差账户（默认公司）
```

## 11. 异常处理

- 支付失败：不切换城市合伙人；
- 支付成功但结算失败：生成独立结算单，进入人工处理；
- 价格版本过期：订单失败或重新确认，不得按旧价格成交；
- 同城并发购买：只允许一个成功；
- 同城并发创建席位：数据库唯一约束保证只保留一个席位；
- 自己接替自己：下单及支付履约均拒绝；旧的已付自我接替订单不得履约，进入平台异常处理，不提供主动退款入口；
- 城市合伙人席位订单：不支持用户端或后台主动退款，未取得席位、结算失败、缺少席位记录时同样禁止；未付款订单仍可取消；重复扣款/取消后晚到支付的自动原路退回、政策调整前已受理退款的对账继续处理，不冲正已取得的席位；
- 用户关系链不足 7 层：未发金额进入公司账户；
- 价格达到上限：按实际价格计算增值；
- 商品成本或售价变化：不影响已锁定订单快照。

## 12. 原版保护与开发约束

1. 不修改原模式已有结算业务含义；
2. 新模式使用独立结算入口；
3. 不删除原市级代理数据和后台功能；
4. 新模式不调用市级代理分润；
5. 不重算历史订单；
6. 新增字段提供默认值，保证旧数据兼容；
7. 新增测试必须包含原模式回归；
8. 测试原模式、新模式、模式切换、退款和并发购买；
9. 所有金额按 Decimal 处理，不使用浮点数参与结算；
10. 所有规则修改都要保留版本和审计记录。

## 13. 验收标准

### 原模式

- 原模式订单金额与改动前一致；
- 市级代理和区域代理仍按原规则获得收益；
- 原模式退款逻辑不变；
- 切换新模式不改变历史原模式订单。

### 新模式商品分润

以售价 1,600、成本 700 为例，分润池必须为 900，并产生：

```text
100.00 + 400.00 + 200.00 + 100.00 + 50.00
+ 25.00 + 12.50 + 6.25 + 3.12 + 3.13
= 900.00
```

并且不生成市级代理分润或原模式分润。

### 城市合伙人轮换

- 每个城市最多一个当前合伙人；
- 新购买成功后旧合伙人立即失效；
- 上一任本金全额返还；
- 上一任获得增值的 40%；
- 增值的 30%进公司账户；
- 增值的 10%给新购买者上级；
- 增值的 20%进运维部账户；
- 分配合计等于新购买者支付金额。

### 模式切换

- 任意时刻只有一个全局模式；
- 订单按照支付成功时锁定模式；
- 历史订单结算和退款不读取当前模式；
- 同一订单不会同时生成两套分润。

## 14. 待最终确认事项

1. 新模式商品分润是否按商品件数计算，本文默认按件；
2. 城市是否按订单收货地址省、市确定，本文默认是；
3. 成本是否使用订单成本快照，本文建议使用；
4. 没有上级时，直推奖和上级金额是否全部进入公司账户；
5. 没有城市合伙人时，100 元是否进入公司账户；
6. 新模式商品分润冻结、释放周期是否沿用原订单售后周期；
7. 城市合伙人席位订单已明确不支持主动退款；付款后未取得席位的异常处理需要平台介入；
8. 达到价格上限后是否继续允许轮换；
9. 新模式是否所有商品参与，还是逐商品配置；
10. 同一用户是否允许持有多个城市席位。

## 15. 最终设计结论

```text
ORIGINAL：原商品分润 + 市级代理体系
CITY_PARTNER：城市合伙人 + 新商品分润体系
```

新模式下没有市级代理；城市数据只用于识别城市，不代表保留市级代理角色。原模式完整保留，模式切换只影响新订单，历史订单按照自身模式和规则快照结算。
