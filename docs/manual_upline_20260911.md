# 七级分润：自动递减 / 手动设置

后台商品管理 → 规则配置 → 七级分润：

- 按 50% 递减（AUTO，原有商品默认）：从直推上级的上级起，连续七级为直推奖的 1/2 至 1/128；按件舍去分以下金额。
- 手动设置（MANUAL）：分别填写第 1 至第 7 级的元/件金额，允许 0，最多两位小数。燃料商品可七级均填 0.20 元，每件七级合计 1.40 元；不依赖商品名称、分类或直推奖是否为 0。

直推奖和城市合伙人奖仍另行填写；手动金额不覆盖直推上级的直推奖。上级不足七级时只给实际存在的上级发放，剩余归公司。商品未开启新模式分润时不发放此类奖励。

切换自动/手动保留手动金额，自动模式忽略手动数组。两种方式都校验城市合伙人奖、直推奖、七级金额之和不超过售价减成本；混合商品订单逐商品采用各自规则。付款快照记录方式、七级金额和计算策略，已付款订单不因商品规则修改或全局模式切换重新计算；退款按原流水冲正。

迁移新增 `product_zone_configs.city_partner_upline_mode`（默认 AUTO）和 `city_partner_upline_amounts`（JSON，存精确十进制字符串）。应用启动通过现有迁移机制自动补齐；旧商品继续自动递减，原分润模式不读取这两个字段。本次没有加入燃料商品专属标识。

验证结果：

- 完整后端、文档及业务边界回归：433 passed，2 subtests passed，无失败或跳过；包含实际 MySQL 的 0.20 × 3 = 0.60 精确存储及订单快照验证。
- 前端计算测试：3 passed；后端 Ruff、改动前端文件 ESLint 通过。
- 实际后台页面：七级各填 0.20 元、保存后重开、单级改为 0.37 元、自动/手动来回切换、恢复 0.20 元均通过；无页面错误或异常 HTTP 响应。
- 本地 MySQL 连续两次迁移通过；后端和后台 Docker 构建成功，更新后的本地五个服务健康。
